# Rooms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rooms inside a property (details, paint list, flooring, files), linked from equipment location, maintenance schedules and service records, behind a Features toggle, and visible in the property report, search and the assistant.

**Architecture:** New `Room` + `RoomPaint` Prisma models with nullable `roomId` FKs on Equipment, ServiceRecord, MaintenanceSchedule and Attachment. Pure helpers in `lib/rooms.ts` (schemas, row mapping, labels, history filter) are unit-tested; DB helpers in `lib/rooms-server.ts`; server actions in `lib/actions/rooms.ts`. UI copies the Warranties pattern (list + dialog, staged uploads).

**Tech Stack:** Next 16.2 (read `node_modules/next/dist/docs/` before using unfamiliar APIs), Prisma 7.9 + SQLite/libsql, react-hook-form + zod, shadcn/Base UI, Vitest (`lib/**/*.test.ts`).

**Spec:** `docs/superpowers/specs/2026-10-21-rooms-design.md`

## Global Constraints

- Feature flag column `roomsEnabled Boolean @default(true)`; `Features` gains `rooms: boolean`, default `true`.
- Every Room field except `name` optional. Upload dir segment `room` (`AttachmentRecordType.ROOM`).
- Room FKs on Equipment/ServiceRecord/MaintenanceSchedule: `onDelete: SetNull`. Room → Property and Attachment → Room, RoomPaint → Room: `onDelete: Cascade`.
- Any `roomId` from a client must be checked to belong to the target's property before saving; an invalid one is a field error `roomId: ["That room isn't on this property."]`.
- With Rooms off: no tab, no room selects/badges/combobox suggestions, no search hits, no report section, no assistant entity. Data untouched.
- Display of an equipment location everywhere: `room?.name ?? location`.
- Verification per task: `npm test`, `npx tsc --noEmit`, `npm run lint`.

## Review Focus

1. Equipment moved to another property while linked to a room → `roomId` must be cleared, not left pointing at the old property's room.
2. Old backups/snapshots without the `roomId` column → `referencedFiles` in `lib/backup/snapshot.ts` must not throw (select `roomId` only if the column exists).
3. Room deleted → equipment keeps a readable location (`location = room.name`), records just lose the badge; room upload dir removed.
4. Property deleted → rooms' upload dirs removed (rooms cascade in DB, files would otherwise orphan).
5. Rooms off but equipment linked to a room → equipment page/list still shows the room name as its location; saving the form unchanged keeps the link.

### Task 2: Pure room helpers

**Files:**
- Create: `lib/rooms.ts`, `lib/rooms.test.ts`

**Interfaces:**
- Produces:
  - `roomSchema` (zod): `propertyId`, `name` (min 1, "Name is required"), `level?`, `area?` (`optionalNumber(z.coerce.number().positive())`), `dimensions?`, `flooringType?`, `flooringProduct?`, `flooringInstalled?` (date string), `notes?`, `paints: { surface: string (min 1), brand?, colorName?, colorCode?, finish? }[]` (default `[]`).
  - `type RoomInput = z.input<typeof roomSchema>`
  - `roomData(v)` → row with blanks as `null`, date parsed.
  - `paintRows(paints)` → rows with blanks `null` and `sortOrder` = index; drops rows whose all fields after trimming are blank.
  - `paintLabel(p)` → e.g. `"Walls: Sherwin-Williams Agreeable Gray SW 7029 · Eggshell"` (parts skipped when null).
  - `FLOORING_SUGGESTIONS = ["Hardwood", "Engineered wood", "Laminate", "Luxury vinyl plank", "Vinyl", "Tile", "Carpet", "Concrete", "Stone"]`
  - `PAINT_SURFACES = ["Walls", "Ceiling", "Trim", "Doors", "Accent wall", "Cabinets"]`
  - `locationLabel(e: { location: string | null; room?: { name: string } | null }): string | null`
  - `type HistoryScope = "own" | "withEquipment"`; `scopeRecords<T extends { assetType: string; assetId: string; roomId?: string | null }>(records: T[], scope, own: { assetType: "PROPERTY"; assetId: string } | { roomId: string }, roomEquipmentIds?: string[]): T[]` — property: `own` keeps only `assetType === "PROPERTY"`; room: `own` keeps `roomId === id`, `withEquipment` adds records whose asset is equipment in `roomEquipmentIds`.
